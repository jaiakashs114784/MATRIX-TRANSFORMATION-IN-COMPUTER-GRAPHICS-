02 THE HOOK

How do robots actually move?

  • A robot arm has no "muscles" or "eyes" — only numbers.
  • Every joint, every motor, every gripper position is a mathematical command.
  • Behind every smooth factory robot is a constant stream of matrix calculations.
  • Today: how a grid of numbers becomes physical motion.
03 THE PROBLEM

Understanding robot motion is hard

  • A robot has many joints moving at the same time — how do we describe that?
  • Saying "move left a bit, then up" doesn't scale to 6-axis industrial arms.
  • We need one language that handles position + orientation together.
  • That language is transformation matrices — compact, exact, and composable.
04 FOUNDATION

Coordinate systems: X, Y, Z

  • Everything a robot does is described relative to a coordinate frame.
  • X → forward/back, Y → left/right, Z → up/down.
  • Each robot joint gets its own frame — the gripper has one, the base has one.
  • Motion = describing how points move from one frame to another.
05 CORE CONCEPT

What is a matrix?

  • A matrix is just a grid of numbers arranged in rows and columns.
  • Think of it as a recipe of instructions for moving points in space.
  • Change the numbers → change the type of motion the robot performs.
  • Robots store entire poses as small matrices — easy to compute, fast to chain.

06 THE TOOLKIT

Types of transformations

  • Translation — slide an object from one place to another.
  • Rotation — turn an object around an axis.
  • Scaling — grow or shrink an object.
  • All three are just different number patterns inside the same matrix format.
07 TRANSFORMATION 01

Translation — movement

  • Translation means sliding an object without turning it.
  • Only the last column changes: it stores "how far" in X, Y, Z.
  • Robot use-case: moving a gripper straight to a part on a conveyor.
  • Think: "walk 3 steps east, 2 steps north" — that's a translation vector.
08 TRANSFORMATION 02

Rotation — turning

  • Rotation turns an object around an axis (X, Y, or Z).
  • The 3×3 corner of the matrix stores how much to turn — using sin/cos angles.
  • Robot use-case: a wrist joint twisting the gripper to align with a part.
  • Key idea: rotating the coordinate frame = same math as rotating the object.
09 TRANSFORMATION 03

Scaling — resize (briefly)

  • Scaling multiplies each axis by a factor: 2× doubles size, 0.5× halves it.
  • Less common for robot motion — robots move rigid bodies that don't change size.
  • Where it matters: simulation & digital twins, camera vision, and CAD models.
  • Same matrix idea: just numbers on the diagonal of the grid.
10 THE SUPERPOWER

Combining transformations

  • Move then turn then move again? Just multiply the matrices.
  • One product = one final matrix describing the entire motion chain.
  • Order matters: rotate → translate ≠ translate → rotate.
  • This is why matrices beat long lists of instructions — one compact result.

11 CASE STUDY

Real world: pick & place

  • Task: grab a part from a conveyor, drop it in a box.
  • Vision system finds the part → its position becomes a coordinate frame.
  • Controller computes the transformation chain: base → shoulder → elbow → wrist → gripper.
  • Each joint matrix multiplies into the next until the gripper matches the part's frame.
12 WALKTHROUGH

Step-by-step: one robot movement

  • Step 1 — Locate the target: convert part position into a target frame.
  • Step 2 — Chain frames: multiply base → joint1 → joint2 → … → gripper matrices.
  • Step 3 — Solve: find joint angles so the final matrix matches the target.
  • Step 4 — Execute: motors turn, gripper lands on the part — exactly where the math said.
13 WHY IT MATTERS

Why matrices are important

  • Universal language — one framework for position, orientation, and motion.
  • Fast — a single matrix multiply replaces many separate calculations.
  • Exact — no guessing; repeatability of fractions of a millimeter.
  • Scalable — the same math works for a 2-joint arm or a humanoid robot.
14 BEYOND THE BASICS

Applications in robotics & automation

  • Industrial arms — welding, painting, assembly on car production lines.
  • Mobile robots — SLAM: mapping rooms and tracking position with transforms.
  • Drones — stabilizing flight by constantly rotating sensor frames.
  • Surgical robots — precise, tremor-free instrument positioning.
  • Game engines & VR — the same math renders 3D worlds in real time.
15 MISSION COMPLETE

Conclusion: matrices = motion

  • Robots don't "see" motion — they compute it, one matrix at a time.
  • Translation moves, rotation turns, scaling resizes — one unified toolkit.
  • Multiply the chain, and complex robot choreography becomes one compact command.
  • Master transformations, and you hold the core language of modern robotics.
